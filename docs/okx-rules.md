# OKX 规则调研

本文是实现的事实依据，按主题组织——每条规则的公式与支撑它的证据放在一起，
不必在「公式」与「验证」两处之间来回翻。

每条规则标注证据等级：

- **实测** —— 在 OKX 模拟盘上执行过真实操作并逐字段核对，给出了差值
- **文档** —— 只与官方帮助中心核对过，未经实盘验证
- **未定** —— 证据不足，代码中不臆造，见第 11 节

约定：`Q = ctVal × |sz| × ctMult`（合约名义数量）。

## 1. 参考数据来源

全部免鉴权，实测可达：

| 用途 | 接口 |
|---|---|
| 合约规格 | `GET /api/v5/public/instruments?instType=SWAP` |
| 档位 / MMR / IMR 表 | `GET /api/v5/public/position-tiers?instType=SWAP&tdMode={cross\|isolated}&instFamily=...` |
| 折算率（跨币种保证金用） | `GET /api/v5/public/discount-rate-interest-free-quota?ccy=...` |
| 当期资金费率 | `GET /api/v5/public/funding-rate?instId=...` |
| 历史资金费率 | `GET /api/v5/public/funding-rate-history?instId=...`（窗口约 3 个月，见 §6） |
| 标记价格 | `GET /api/v5/public/mark-price?instType=SWAP&instId=...` |

费率不在此列：`/api/v5/account/trade-fee` 需要鉴权且返回的是「当前账户」的费率。

实测样本：

```
BTC-USDT-SWAP  ctType=linear   ctVal=0.01 BTC  ctMult=1  settleCcy=USDT  lotSz=minSz=0.01  maxLever=100
BTC-USD-SWAP   ctType=inverse  ctVal=100 USD   ctMult=1  settleCcy=BTC   lotSz=minSz=0.1   maxLever=100
```

档位表 **99 档**（cross 与 isolated 是两张独立的表）：

```
tier1  sz[0,        1000 ]  mmr=0.004   imr=0.01   maxLever=100
tier2  sz[1000.01,  5000 ]  mmr=0.005   imr=0.015  maxLever=66.66
tier3  sz[5000.01,  20000]  mmr=0.0075  imr=0.02   maxLever=50
tier4  sz[20000.01, 40000]  mmr=0.0125  imr=0.025  maxLever=40
tier5  sz[40000.01, 60000]  mmr=0.0175  imr=0.03   maxLever=33.33
```

`mmr` 的跳幅逐档加大（0.004 → 0.005 → 0.0075 → 0.0125 → 0.0175），
杠杆上限相应收窄——仓位越大，风控越严。

⚠️ 档位下界的递增步长跟随 `lotSz`：USDT 本位是 `1000.01`，币本位是 `2000.1`。
**这种边界不可推导，只能读表。**

⚠️ 各品种的档位表**互不相同**，不可去重。曾设想按「阶梯形状」共享，实测 30 个
品种里 28 张表各异，且 BTC 与 DOGE 连首档的 `mmr` 与杠杆都不同
（`0.004/100x` vs `0.01/50x`）。

## 2. 字段语义陷阱

**实测。** 这几个字段的名字与实际含义不符，是「字段级同构」最容易翻车的地方。

| 字段 | 看起来是 | 实际是 |
|---|---|---|
| `position.mmr` | 维持保证金**率** | 维持保证金**金额**（如 47.91 USDT） |
| `position.realizedPnl` | 毛已实现盈亏 | **净额** = 毛盈亏 + 手续费 + 资金费 + 爆仓罚金 |
| `order.fillSz` | 累计成交量 | **最新一笔**成交的数量 |
| `order.accFillSz` | — | 累计成交量，这个才等于全部成交后的 `sz` |
| `balance.frozenBal` | 挂单冻结 | 逐仓权益 + 挂单冻结 |
| `balance.ordFrozen` | 挂单冻结总额 | 只有**保证金部分**，不含预冻结的手续费 |
| `position.imr` | 初始保证金 | 逐仓恒为空串，保证金看 `margin` |

`realizedPnl` 的净额构成经真实数据确证，差值为零：

```
182.04988519038076 + (-10.066836395) + (-75.53442700159925) + 0  =  96.44862179378151
毛盈亏               手续费             资金费                  罚金 = OKX 的 realizedPnl
```

把毛额填进 `realizedPnl`，长期持仓的对账会差出全部的手续费与资金费——
该样本里就是 85.6。

OKX 用**空串**区分「无此值」与「值为零」。把逐仓的 `imr` 空串写成 `"0"`，
下游会误以为初始保证金真的是零。

## 3. 仓位与盈亏

### 已实现盈亏

**实测**，差值 `1.6e-15`：

```
linear  多: Q × (closePx − avgPx)
linear  空: Q × (avgPx − closePx)
inverse 多: Q × (1/avgPx − 1/closePx)
inverse 空: Q × (1/closePx − 1/avgPx)
```

样本：ETH-USDT-SWAP 逐仓多头 49.18 张，开仓均价 `1805.5767334669338683`，
平仓均价 `2434.9135176901179344`，算得 `3095.0783048096192370798`，
OKX 返回 `3095.0783048096192355`。

### 未实现盈亏

**实测**，差值 `4.6e-13`。同上式，`closePx` 换成**标记价**——不是最新成交价。

### 收益率

**实测**，分母是**开仓时**的初始保证金 `Q × avgPx / lever`，不是当前 `margin`。

两者在开仓瞬间相等，逐仓的资金费从保证金里扣，持仓久了才分离。只有那个持有
七周的样本能区分：`margin` 比开仓初始保证金少 75.36，用当前 `margin` 算得
`1.8216`，用开仓初始保证金算得 `1.7443`——OKX 给的是后者。

### 均价与反手

**文档 + 实测**：

- **部分平仓不改变开仓均价**，只结算已实现盈亏；只有加仓才做加权平均
- **买卖模式(net)的反手**：卖出量超过多头持仓时，先平光再反向开空，均价重置为成交价
- 开平仓模式下不会反手——**超量平仓会被裁剪**（见 §8）

## 4. 保证金与风险指标

### 初始保证金

```
linear :  Q × px / lever
inverse:  Q / (px × lever)
```

逐仓的 `margin` 按**成交价**计算并在开仓时从现金余额划走（见 §5）。

### 维持保证金

**单档整体适用，不是分层累进。** 落在第 N 档就整体乘以第 N 档的 `mmr`，
不逐档累加。

> 这是第三方实现最常见的错误来源——很多实现照搬了阶梯税式的累进算法。

⚠️ 档位按 **`instFamily`** 聚合，不是 `instId`。全仓模式下 `BTC-USDT-SWAP` 与
`BTC-USDT-260327` 的持仓要合并后再查档。按 `instId` 建模，后期必须推倒重来。

### 保证金率

**实测**，差值 `2.2e-14`：

```
mgnRatio = (逐仓保证金 + 未实现盈亏) / (维持保证金金额 + 平仓手续费)
```

以**倍数**表示，`1` 即 100%，**≤ 1 触发强平**。实测一个健康的五倍杠杆浮盈仓位
其 `mgnRatio` 为 `89.03`，即 8903%。

全仓的账户级口径（**文档**，v0.5.0 才实现）：

```
该币种全仓余额 + 全仓收益 − 挂单卖出占用 − 期权买单占用 − 逐仓开仓占用 − 挂单手续费
```

### 预估强平价

**实测**，五个独立样本横跨 `tickSz` 三个量级、杠杆 5x 与 50x/100x、多空两侧，
差值 `1e-16` 至 `1e-19`：

```
多: (avgPx×Q − margin) / (Q × (1 − mmr − taker)) + tickSz
空: (avgPx×Q + margin) / (Q × (1 + mmr + taker)) − tickSz
```

末尾那**一个 tickSz 是 OKX 的安全缓冲**，方向朝更早触发强平的一侧。
任何文档都没有写这一项——四个标定样本的「偏移 ÷ tickSz」全部为 ±1。
少了它，强平价会系统性偏乐观一个 tick，在对拍时表现为一个甩不掉的偏差。

### 破产价

权益恰好归零的价格：`多: avgPx − margin/Q`，`空: avgPx + margin/Q`。

## 5. 手续费与资金流转

### 费率

**实测**：Lv1 永续 maker `-0.0002` / taker `-0.0005`。

**负数表示收取、正数表示返佣**，这是 OKX 的符号约定。保留符号能让手续费直接
参与余额加法，调用处无需判断正负。

计费币种跟随 `settleCcy`：linear 收 USDT，inverse 收标的币。开仓与平仓均按成交
名义价值计费，差值 `6.9e-19`。

一笔市价单会被拆成多笔成交（样本中 15 笔），逐笔独立计费，
**逐笔 fee 之和精确等于订单级 fee**。

费率还有 `feeGroup` 维度：合约规格里的 `groupId` 指向费率表的费率组。
永续下各组取值一致，现货则差异显著（组 3 taker 0.22%、组 8 是 0.4%、组 11 免费）。

### 逐仓账务

**实测**，各项差值恰为 0：

| 环节 | 规则 |
|---|---|
| 开仓 | 现金减少「保证金 + 手续费」，**手续费从现金扣、不计入保证金** |
| 部分平仓 | 保证金**按张数比例**释放：`624.705284 × 1/4 = 156.176321` |
| 平仓 | 现金增加「释放的保证金 + 已实现盈亏 + 手续费」 |
| 全程 | 现金净变化 = 盈亏合计 + 手续费合计 |

字段关系：

```
isoEq     = margin + upl
frozenBal = isoEq + 挂单冻结
eq        = cashBal + isoEq
availBal  = cashBal − 挂单冻结(保证金 + 手续费)
```

### 挂单冻结

**实测**，差值为 0：

| 情形 | 冻结 |
|---|---|
| 开仓方向的挂单 | 张数 × (每张保证金 + 每张 **taker** 手续费) |
| 平仓方向的挂单 | **不冻结任何资金** |
| 反手委托 | 只对开仓那一段冻结 |

手续费一律按 **taker 费率**预冻结，即便该委托必然作为 maker 成交——实测一笔
远离市价、必然挂住的限价单也是按 taker 冻结的，OKX 取保守值。

### 可开张数

`GET /api/v5/account/max-size`，**实测**七组价格全部命中：

| | 取价规则 |
|---|---|
| `maxBuy` | 按**委托价**，无论其高于还是低于标记价 |
| `maxSell` | 在委托价与标记价之间取**更保守**的一侧，即张数更少者 |

张数 = 可用余额 ÷ (每张保证金 + 每张手续费)，按 `lotSz` 向下取整。

这个不对称是 OKX 自身的行为而非可推导的原理：委托价高于标记价的买单本会立即
以标记价附近成交、所需保证金更少，OKX 仍按委托价计算。此处照实记录。

### 逐仓保证金增减

**实测**：`POST /api/v5/account/position/margin-balance` 一比一划转，杠杆设置不变，
强平价随之远离（追加 200 时 `62772 → 57750`）。

减少的下限是**开仓时的初始保证金** `Q × avgPx / lever`，等价于不允许有效杠杆
超过设定杠杆。越限时返回 `59301`。

下限按开仓均价而非标记价算：实测减到 `624.900524` 恰等于按开仓均价算出的初始
保证金，再减即被拒；若按标记价算下限应为 `624.96296`，比当时的保证金还高，
那样当前状态本身就已违规，与实际矛盾。

## 6. 资金费

**实测**，与真实账单逐位相同：

```
资金费 = ctVal × sz × ctMult × 结算价 × 费率
fundingRate > 0：多头付空头
```

样本 `sz=49.18, px=2454.22, rate=0.0001` 算得 `1.206985396`。

**逐仓的资金费从仓位保证金里扣，不动现金余额。** 账单确证：连续多期结算中
`balChg` 恒为 0、`bal` 纹丝不动，而 `posBalChg` 恰为资金费金额、`posBal` 逐次递减。
记到现金余额上会让逐仓权益与强平价一起算错。

### 结算周期与费率上下限

**实测**采样 49 个永续：**16 个为 4 小时、33 个为 8 小时**，未观察到 1 小时周期。
**周期必须从 `fundingTime` / `nextFundingTime` 读取，不要硬编码。**

费率上下限也随合约而异，实测三档：`±0.01`（43 个）、`±0.0075`（4 个）、
`±0.00375`（2 个）。

### ⚠️ 历史费率只有约 3 个月

`funding-rate-history` 免鉴权可翻页，但**回溯窗口有硬限制**。实测翻到底：

| 合约 | 条数 | 最早 | 距今 |
|---|---|---|---|
| BTC-USDT-SWAP | 294 | 2026-05-25 | 97 天 |
| ETH-USDT-SWAP | 293 | 2026-05-25 | 97 天 |
| DOGE-USDT-SWAP | 293 | 2026-05-25 | 97 天 |
| BTC-USD-SWAP | 294 | 2026-05-25 | 97 天 |

四者截止在**同一天**，说明这是平台级窗口而非个别合约的问题。

**后果：超出约 3 个月的回测取不到真实资金费率。** 结算机制本身已按真实账单
验证无误，但它只在调用方能提供费率时才有意义。长周期回测须自行选择：接第三方
数据源、用常数近似（观测到的费率多为 `0.0001`，即 OKX 的基础利率），或不计
资金费——最后一种会**系统性高估多头持仓的收益**。

## 7. 强平

### 触发

**实测**：`mgnRatio ≤ 1`，即权益 ≤ 维持保证金 + 平仓手续费。

判据用**标记价**而非最新成交价——用最新价会让插针扫掉本不该爆的仓位。

### 结算方式

**实测**，取自一次真实的全部强平。样本：BTC-USDT-SWAP 空头 0.15 张 @ 78099，
100 倍杠杆，保证金 `1.171485`，强平价 `78526.61`。

```
订单     category='full_liquidation'  ordType=limit  reduceOnly=true
         成交价 78566.58（已越过强平价）  pnl=-0.70137  fee=-0.058924935
仓位历史  liqPenalty=-0.47139948   realizedPnl=-1.290268665
账单     type=5  subType=105   balChg=0   posBalChg=-1.231694415
         type=10 subType=108   balChg=0   posBalChg=+0.060209415
```

由此确定的规则，各项差值均为零：

| 项 | 规则 |
|---|---|
| 成交价 | **触发时的市价**，可能已越过强平价 |
| 盈亏 | 按该成交价计算 |
| 手续费 | 名义价值 × taker 费率 |
| **爆仓罚金** | **名义价值 × 维持保证金率**（`0.47139948 / 117.84987 = 0.004`，正是 mmr） |
| 损失 | **封顶为该仓位的保证金**；超出部分以单独账单退回 |
| **现金余额** | **`balChg = 0`，自始至终不变** |

两笔账单之和 `-1.231694415 + 0.060209415 = -1.171485`，恰好等于开仓保证金——
**保证金不多不少全额损失**。

净已实现盈亏也精确对上：
`开仓费 -0.05857425 + 平仓盈亏 -0.70137 + 平仓费 -0.058924935 + 罚金 -0.47139948
= -1.290268665`，与 `positions-history` 的 `realizedPnl` 一致。

> 早先曾按「成交于费后破产价、罚金为零」建模。净效果相同——保证金全损、现金不变
> ——但 `pnl`、`fee`、`liqPenalty`、`realizedPnl` 四个字段全都对不上。
> **净效果相同不等于字段相同**，而字段级同构正是本项目的验收标准之一。

常态强平也会有小幅超出——触发与成交之间价格总会再走一点，实测那次为 `0.0602`，
占保证金的 5%，OKX 以单独账单退回。「常态超出为零」是错的期望。

### 阶梯减仓（**未定**）

真实链路是 `撤单 → 阶梯部分减仓 → 全部强平`。减仓后持仓量落入更低档位，
维持保证金率随之下降，仓位有机会被救回——降档使保证金率乘以
`(mmr₂ + taker) / (mmr₁ + taker)`，大于 1 即能救回。

**该路径尚未实测。** 触发它需要跨越多个档位的仓位。已在 FIL-USDT-SWAP 上布好
二档纵深的双向仓位等待触发。当前实现依据 OKX 的阶梯档位规则，未经验证。

## 8. 下单校验

**实测**：

- **超量平仓会被裁剪而非拒绝**。提交 1.50 张去平一个 0.15 张的仓位，OKX 把 `sz`
  直接裁剪到 0.15 后成交（订单记录里的 `sz` 就是 0.15）。
- **数量必须是 `lotSz` 的整数倍**，否则返回 `51121`。实测 459 个永续的 `minSz`
  与 `lotSz` **全部相等**，故「低于最小下单量」与「非整数倍」是同一件事。
- **价格超精度不会被拒绝**，OKX 按方向取整后接受：

```
买单  2150.51 / 2150.55 / 2150.59  →  2150.5   向下截断
卖单  2376.91 / 2376.95 / 2376.99  →  2377     向上进位
```

三个合约、`tickSz` 横跨 `0.1 / 0.01 / 1e-7`，无一被拒。两个方向都朝远离市价的
一侧移动，即让委托更不激进。

**因此模拟器不应强制校验价格精度**——强制拒单会拒掉真实 OKX 会接受的订单，
回测中凭空少掉成交，与还原真实行为正好相反。

## 9. ⚠️ 模拟盘 ≠ 生产环境

**实测**。这是对拍策略中最容易埋雷的一点。

| 合约 | 字段 | 生产 | 模拟盘 |
|---|---|---|---|
| BTC-USDT-SWAP | tickSz | 0.1 | **0.01** |
| DOGE-USDT-SWAP | tickSz | 0.00001 | **0.0000001** |
| YFI-USDT-SWAP | tickSz | 1 | **0.1** |
| YFI-USDT-SWAP | lever | 20 | **50** |
| BTC-USD-SWAP | lever | 100 | **125** |

档位表差异更彻底：

| 品种 | 差异 |
|---|---|
| BTC-USDT / ETH-USDT | 档位区间上界是生产的 **10 倍**（BTC 首档 1000 → 10000），99 档全部不同 |
| BTC-USD | 档位数 **99 vs 100**，且 `imr` 0.01 → 0.008、`maxLever` 100 → 125 |

**对拍工具必须从它所交易的同一环境拉取规则数据。** 拿生产快照去对拍模拟盘，
每个依赖档位、价格精度或杠杆的计算都会偏，而偏差看起来像模拟器自身的缺陷，
会把大量时间浪费在追查根本不存在的问题上。

随库分发的内置快照取自**生产环境**，仅供回测；对拍模拟盘须用
`live.WithSimulated(true)`。

## 10. 错误码

**全部实测取得**，未经证实的码不予收录。

| 码 | 含义 | 实测触发条件 |
|---|---|---|

## 11. 尚未定论

代码中不臆造这些规则，并留有守卫测试防止前提悄悄失效。

**费率组与结算币种变体的优先级。** 实测 459 个永续的 `groupId` 均为 4，且 SWAP
费率表 1..7 组与 `maker/taker/makerU/takerU` 取值完全一致，两条路径给出同一个
数字，无从判定。现采用**费率组优先**——这是使用者拍板的决定而非实测结论，
依据是现货各费率组差异显著，说明它是 OKX 用于精细区分的维度。
`TestSwapFeePathsCurrentlyAgree` 会在两条路径开始分歧时失败。

**阶梯减仓路径。** 见 §7。

## 12. 建模时的高风险点

按踩坑代价排序。前三条已在本实现中处理，后三条属于尚未支持的范围。

1. **档位按 `instFamily` 聚合，不是 `instId`**（§4）。按 `instId` 建模，
   后期必须推倒重来——因此数据模型第一天就要以 `instFamily` 为聚合键。
2. **买卖模式的反手**（§3）。常见错误是把整笔成交都当成平仓（盈亏算多），
   或都当成开仓（漏掉已实现盈亏）。
3. **字段语义陷阱**（§2）。名字与含义不符的字段有七个之多。
4. **全仓强平是账户级的**（按 `settleCcy` 分币种），逐仓才是仓位级。
   两者是完全不同的代码路径，不要试图复用。
5. **组合保证金 (acctLv=4) 的 MMR 由压力测试矩阵得出**，不是查表。
   工作量约等于本项目其余部分之和，已明确排除在 v1.0 范围外。
6. **跨币种保证金 (acctLv=3)** 需要折算率、跨币种借币计息与账户整体 USD 折算。
