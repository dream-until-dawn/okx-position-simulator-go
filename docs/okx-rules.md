# OKX 规则调研

本文是实现的事实依据，按主题组织——每条规则的公式与支撑它的证据放在一起，
不必在「公式」与「验证」两处之间来回翻。

每条规则标注证据等级：

- **实测** —— 在 OKX 模拟盘上执行过真实操作并逐字段核对，给出了差值
- **文档** —— 只与官方帮助中心核对过，未经实盘验证
- **未定** —— 证据不足，代码中不臆造，见第 12 节

约定：`Q = ctVal × |sz| × ctMult`（合约名义数量）。

## 1. 参考数据来源

全部免鉴权，实测可达：

| 用途 | 接口 |
|---|---|
| 合约规格 | `GET /api/v5/public/instruments?instType=SWAP` |
| 档位 / MMR / IMR 表 | `GET /api/v5/public/position-tiers?instType=SWAP&tdMode={cross\|isolated}&instFamily=...` |
| 折算率（跨币种保证金用） | `GET /api/v5/public/discount-rate-interest-free-quota?ccy=...` |
| 当期资金费率 | `GET /api/v5/public/funding-rate?instId=...` |
| 历史资金费率 | `GET /api/v5/public/funding-rate-history?instId=...`（窗口约 3 个月，见 §6） |
| 标记价格 | `GET /api/v5/public/mark-price?instType=SWAP&instId=...` |

费率不在此列：`/api/v5/account/trade-fee` 需要鉴权且返回的是「当前账户」的费率。

实测样本：

```
BTC-USDT-SWAP  ctType=linear   ctVal=0.01 BTC  ctMult=1  settleCcy=USDT  lotSz=minSz=0.01  maxLever=100
BTC-USD-SWAP   ctType=inverse  ctVal=100 USD   ctMult=1  settleCcy=BTC   lotSz=minSz=0.1   maxLever=100
```

档位表 **99 档**（cross 与 isolated 是两张独立的表）：

```
tier1  sz[0,        1000 ]  mmr=0.004   imr=0.01   maxLever=100
tier2  sz[1000.01,  5000 ]  mmr=0.005   imr=0.015  maxLever=66.66
tier3  sz[5000.01,  20000]  mmr=0.0075  imr=0.02   maxLever=50
tier4  sz[20000.01, 40000]  mmr=0.0125  imr=0.025  maxLever=40
tier5  sz[40000.01, 60000]  mmr=0.0175  imr=0.03   maxLever=33.33
```

`mmr` 的跳幅逐档加大（0.004 → 0.005 → 0.0075 → 0.0125 → 0.0175），
杠杆上限相应收窄——仓位越大，风控越严。

⚠️ 档位下界的递增步长跟随 `lotSz`：USDT 本位是 `1000.01`，币本位是 `2000.1`。
**这种边界不可推导，只能读表。**

⚠️ 各品种的档位表**互不相同**，不可去重。曾设想按「阶梯形状」共享，实测 30 个
品种里 28 张表各异，且 BTC 与 DOGE 连首档的 `mmr` 与杠杆都不同
（`0.004/100x` vs `0.01/50x`）。

## 2. 字段语义陷阱

**实测。** 这几个字段的名字与实际含义不符，是「字段级同构」最容易翻车的地方。

| 字段 | 看起来是 | 实际是 |
|---|---|---|
| `position.mmr` | 维持保证金**率** | 维持保证金**金额**（如 47.91 USDT） |
| `position.realizedPnl` | 毛已实现盈亏 | **净额** = 毛盈亏 + 手续费 + 资金费 + 爆仓罚金 |
| `order.fillSz` | 累计成交量 | **最新一笔**成交的数量 |
| `order.accFillSz` | — | 累计成交量，这个才等于全部成交后的 `sz` |
| `balance.frozenBal` | 挂单冻结 | 逐仓权益 + 挂单冻结 |
| `balance.ordFrozen` | 挂单冻结总额 | 只有**保证金部分**，不含预冻结的手续费 |
| `position.imr` | 初始保证金 | 逐仓恒为空串，保证金看 `margin` |

`realizedPnl` 的净额构成经真实数据确证，差值为零：

```
182.04988519038076 + (-10.066836395) + (-75.53442700159925) + 0  =  96.44862179378151
毛盈亏               手续费             资金费                  罚金 = OKX 的 realizedPnl
```

把毛额填进 `realizedPnl`，长期持仓的对账会差出全部的手续费与资金费——
该样本里就是 85.6。

OKX 用**空串**区分「无此值」与「值为零」。把逐仓的 `imr` 空串写成 `"0"`，
下游会误以为初始保证金真的是零。

## 3. 仓位与盈亏

### 已实现盈亏

**实测**，差值 `1.6e-15`：

```
linear  多: Q × (closePx − avgPx)
linear  空: Q × (avgPx − closePx)
inverse 多: Q × (1/avgPx − 1/closePx)
inverse 空: Q × (1/closePx − 1/avgPx)
```

样本：ETH-USDT-SWAP 逐仓多头 49.18 张，开仓均价 `1805.5767334669338683`，
平仓均价 `2434.9135176901179344`，算得 `3095.0783048096192370798`，
OKX 返回 `3095.0783048096192355`。

### 未实现盈亏

**实测**，差值 `4.6e-13`。同上式，`closePx` 换成**标记价**——不是最新成交价。

### 收益率

**实测**，分母是**开仓时**的初始保证金 `Q × avgPx / lever`，不是当前 `margin`。

两者在开仓瞬间相等，逐仓的资金费从保证金里扣，持仓久了才分离。只有那个持有
七周的样本能区分：`margin` 比开仓初始保证金少 75.36，用当前 `margin` 算得
`1.8216`，用开仓初始保证金算得 `1.7443`——OKX 给的是后者。

### 均价与反手

**文档 + 实测**：

- **部分平仓不改变开仓均价**，只结算已实现盈亏；只有加仓才做加权平均
- **买卖模式(net)的反手**：卖出量超过多头持仓时，先平光再反向开空，均价重置为成交价
- 开平仓模式下不会反手——**超量平仓会被裁剪**（见 §8）

## 4. 保证金与风险指标

### 初始保证金

```
linear :  Q × px / lever
inverse:  Q / (px × lever)
```

逐仓的 `margin` 按**成交价**计算并在开仓时从现金余额划走（见 §5）；全仓的 `imr`
按**标记价**计算，钱不划走（见「全仓账务」）。

两类合约均已实测（BTC-USD-SWAP 逐仓 `margin` 差 1e-18、全仓 `imr` 差 3e-17）。
反向合约的 `Q` 单位是**计价币**（如 USD），除以价格才得到标的币金额——这一步是
币本位一切差异的源头，其余公式都只是它的自然结果。

### 维持保证金

**单档整体适用，不是分层累进。** 落在第 N 档就整体乘以第 N 档的 `mmr`，
不逐档累加。

> 这是第三方实现最常见的错误来源——很多实现照搬了阶梯税式的累进算法。

#### 查档的口径（**实测**）

档位表的键是 **`(instType, instFamily, mgnMode)`**，三者缺一不可：

| | |
|---|---|
| 不是 `instId` | 全仓下同品种同产品类型的多个合约要合并查档，按 `instId` 建模后期必须推倒重来 |
| **必须带 `instType`** | 同一 `instFamily` 下永续与交割**不共用一张表**，详见下方 |
| 必须带 `mgnMode` | 逐仓与全仓是两张独立的表，且查档口径本身也不同 |

**两种模式的查档口径互补：**

| 模式 | 口径 |
|---|---|
| 逐仓 | 每个仓位单独查。同一 `instId` 的多空两个仓位也各查各的 |
| 全仓 | 同一 `(instType, instFamily)` 下全部持仓的**张数绝对值合计**后查一次，结果对该家族每个仓位一体适用 |

证据：

- **全仓合并**——两个交割期各持 7000 张（一档上限 12500）。先开的那条腿**一张未动**，
  仅因另一期开了仓，其维持保证金率就从 `0.01` 跳到 `0.015`
- **按绝对值而非净额**——同一合约多空各 7000 张，净额为零，两个仓位的维持保证金率
  仍是 `0.015`，只有按绝对值合计 14000 张才查得到
- **逐仓不合并**——FIL-USDT 多空各 50 万张，合计 100 万本应落在第三档（`mmr 0.03`），
  实际两个仓位都是 `0.015`，正是各自按 50 万张单独查档的结果

**永续与交割不共用档位表**，同为 `GRASS-USDT` 家族：

| | `ctVal` | 一档上限 | 折合标的币 | `mmr` | 杠杆上限 |
|---|---|---|---|---|---|
| 永续 | 10 | 10000 张 | **100,000** | 0.02 | 20 |
| 交割 | 1 | 12500 张 | **12,500** | 0.01 | 50 |

名义口径差 8 倍、维持保证金率差一倍、杠杆上限差 2.5 倍——不可能是同一条阶梯的
两种表述，因此两者的持仓也不合并。

#### 档位表里的 `imr` 不是初始保证金率（**实测**）

它只用于倒推该档的杠杆上限（`maxLever = 1/imr`）。仓位的实际初始保证金**始终**
是 `名义 / 用户设定的杠杆`：实测二档 `imr=0.025`（即杠杆 ≤ 40），而用户设了 20 倍，
仓位 `imr` 字段给的就是 `名义/20`。

### 保证金率

**实测**，差值 `2.2e-14`：

```
mgnRatio = (逐仓保证金 + 未实现盈亏) / (维持保证金金额 + 平仓手续费)
```

以**倍数**表示，`1` 即 100%，**≤ 1 触发强平**。实测一个健康的五倍杠杆浮盈仓位
其 `mgnRatio` 为 `89.03`，即 8903%。

全仓的口径是**结算币种级**的，不是仓位级的（**实测**，无漂移的快照差 `5e-15`）：

```
mgnRatio = (现金余额 + 全仓浮盈) / (全仓维持保证金 + Σ全仓仓位平仓手续费)
```

结构与逐仓完全一致，差别只在「权益」的定义：逐仓是仓位自己的保证金加浮盈，
全仓是整个币种的现金加浮盈。**逐仓的权益完全不参与全仓的风险计算**——币种级的
`imr`/`mmr` 实测只覆盖全仓仓位，当时账上同时持有三个逐仓仓位、`isoEq` 达 1609，
一分钱都没算进去。

OKX 在全仓**仓位级**返回的 `mgnRatio` 就是这个币种级的值原样重复到每个仓位上。

> `acctLv=2` 下账户级的 `adjEq`/`availEq`/`imr`/`mmr`/`mgnRatio` 实测**恒为空串**
> ——风险按结算币种分别核算，不做全账户折算。跨币种折算是 `acctLv=3` 的事。

### ⚠️ 全仓保证金率有个结构性下限（**推得**）

```
下限 = 1 / (该档最高杠杆 × (维持保证金率 + 吃单费率))
```

开仓时权益最少也要等于初始保证金 `名义/最高杠杆`，而保证金率的分母是
`名义 × 维持保证金率 + 平仓手续费`。两者都正比于名义价值，**比值由档位表锁死**
——放多少钱、加多少仓、烧多少手续费都改不了它。

| 品种 | 档 | 最高杠杆 | mmr | 保证金率下限 | 触发所需不利波动 |
|---|---|---|---|---|---|
| ETH-USD | 一 | 100 | 0.004 | 2.222 | **0.550%** |
| ETH-USD | 二 | 66.66 | 0.005 | 2.727 | **0.950%** |
| ETH-USD | 三 | 50 | 0.0075 | 2.500 | 1.200% |

（ETH-USDT 与 BTC-USDT 的前三档实测与此逐值相同。）

两个实际后果：

1. **全仓账户不可能在没有不利波动的情况下被强平。** 实测 ETH-USD 二档的起点是
   2.73~2.76，与算出的 2.728 相符。想在模拟盘上复现一次全仓爆仓，靠把资金划走或
   烧手续费都压不下去——**只能等价格**
2. **触发所需的不利波动 = `1/最高杠杆 − (维持保证金率 + 吃单费率)`。**
   用满一档的 100x 只需 0.55%，而二档的 66.66x 要 0.95%——**杠杆开得越满，
   离强平反而越近**，因为初始保证金这条起跑线被压低了

若哪天算出低于该下限的保证金率，那一定是分子分母口径错位（分母漏了平仓手续费，
或初始保证金按标记价而非开仓价算），而不是真的更危险。


### 预估强平价

**实测**，五个独立样本横跨 `tickSz` 三个量级、杠杆 5x 与 50x/100x、多空两侧，
差值 `1e-16` 至 `1e-19`：

```
多: (avgPx×Q − margin) / (Q × (1 − mmr − taker)) + tickSz
空: (avgPx×Q + margin) / (Q × (1 + mmr + taker)) − tickSz
```

末尾那**一个 tickSz 是 OKX 的安全缓冲**，方向朝更早触发强平的一侧。
任何文档都没有写这一项——四个标定样本的「偏移 ÷ tickSz」全部为 ±1。
少了它，强平价会系统性偏乐观一个 tick，在对拍时表现为一个甩不掉的偏差。

#### 反向合约的强平价（**实测**）

名义价值是 `Q/px`，随价格反比变化，故解出来是正向公式的**倒数对偶**：

```
多  Q × (1 + r) / (margin + Q/avgPx) + tickSz
空  Q × (1 − r) / (Q/avgPx − margin) − tickSz        r = mmr率 + taker
```

**那一个 tickSz 的安全缓冲反向合约同样有，方向也一致。** 实测 BTC-USD-SWAP 多空
各一个仓位，「偏移 ÷ tickSz」分别为 `−0.9999999997` 与 `+0.9999999995`，补上后
残差降到 `5e-11`。

⚠️ **币本位空头的亏损有上界。** `Q(1/P − 1/avgPx)` 在 `P → ∞` 时收敛于 `−Q/avgPx`
——价格涨到无穷，名义价值趋近于零。保证金若已覆盖这个上界，**价格再怎么涨也爆不掉**，
此时分母 `Q/avgPx − margin ≤ 0`，应当返回「无强平价」而不是一个负数。正向合约的
空头没有这个性质，亏损随价格线性发散。照搬正向公式会在这里给出荒谬的值。

#### 全仓的强平价（**实测**）

由「币种全仓权益恰好等于维持保证金加平仓手续费」解出。权益、维持保证金与平仓费
都随价格线性变化，故在档位不变的前提下有闭式解：

```
P = (Σ sᵢ·Qᵢ·avgPxᵢ − 现金余额) / (Σ sᵢ·Qᵢ − Σ Qᵢ·(mmr率 + taker))     s = +1 多 / −1 空
```

这正是上面逐仓公式的推广：单个仓位、把现金余额换成该仓位的保证金即退化为它。

反向合约同样是倒数对偶（实测差 `6.3e-13`）：

```
P = (Σ sᵢ·Qᵢ + Σ Qᵢ·(mmr率 + taker)) / (现金余额 + Σ sᵢ·Qᵢ/avgPxᵢ)
```

与逐仓有两处实测差异：

- **全仓没有那一个 tickSz 的缓冲。** 三个样本与本式的差都在 `1e-15` 量级，
  加上缓冲反而会差整整一个 tick
- **分子只用现金余额**，逐仓权益不参与。用 `现金 + isoEq` 会差 7.4

OKX 在三种情形下返回空串（13 个样本无一例外）：

| 情形 | 缘由 |
|---|---|
| 同币种下有**多个合约** | 两个交割期的标记价并不同步，单一强平价无从定义 |
| 解为负 | 现金相对仓位太厚，价格到不了那里 |
| 反向合约 | 本项目待 v0.6.0 |

第一条值得当心：两个交割期各持 7000 张时 OKX 返回空串，而本式仍能解出 `0.1449`
这个**看似合理**的数（当时市价 0.359）。正因为看似合理，才更不能给。

挂单不参与计算：末两个快照上挂着一笔 5000 张的委托，OKX 给出的强平价与没挂单时
逐位相同。

### 破产价

权益恰好归零的价格。它是强平价公式在 `r = 0`（不含维持保证金与手续费）时的特例：

```
正向  多: avgPx − margin/Q            空: avgPx + margin/Q
反向  多: Q / (margin + Q/avgPx)      空: Q / (Q/avgPx − margin)
```

### 盈亏平衡价 `bePx`（**实测**）

平仓后不赚不亏所需的价格：

```
多:  avgPx × (1 + taker) / (1 − taker)
空:  avgPx × (1 − taker) / (1 + taker)
```

平仓那笔手续费按**平仓价**收取，未知数在等式两侧都出现，故不能写成
`avgPx × (1 + 2×taker)`。实测 `avgPx=2445.6`、`taker=0.0005` 时本式给出
`2448.0468234117056`，与 OKX 逐位相同；近似式给出 `2448.0456`，差 1.2 个价位。

手续费一律按吃单费率计，OKX 的 `bePx` 不区分成交角色。

**反向合约完全同式**，无需分支（实测 BTC-USD-SWAP 多空两侧差 `8e-11`）——手续费
按名义价值的固定比例收取，而平衡条件里名义价值被约掉了，与合约类型无关。

## 5. 手续费与资金流转

### 费率

**实测**：Lv1 永续 maker `-0.0002` / taker `-0.0005`。

**负数表示收取、正数表示返佣**，这是 OKX 的符号约定。保留符号能让手续费直接
参与余额加法，调用处无需判断正负。

计费币种跟随 `settleCcy`：linear 收 USDT，inverse 收标的币。开仓与平仓均按成交
名义价值计费，差值 `6.9e-19`。

一笔市价单会被拆成多笔成交（样本中 15 笔），逐笔独立计费，
**逐笔 fee 之和精确等于订单级 fee**。

费率还有 `feeGroup` 维度：合约规格里的 `groupId` 指向费率表的费率组。
永续下各组取值一致，现货则差异显著（组 3 taker 0.22%、组 8 是 0.4%、组 11 免费）。

### 逐仓账务

**实测**，各项差值恰为 0：

| 环节 | 规则 |
|---|---|
| 开仓 | 现金减少「保证金 + 手续费」，**手续费从现金扣、不计入保证金** |
| 部分平仓 | 保证金**按张数比例**释放：`624.705284 × 1/4 = 156.176321` |
| 平仓 | 现金增加「释放的保证金 + 已实现盈亏 + 手续费」 |
| 全程 | 现金净变化 = 盈亏合计 + 手续费合计 |

字段关系：

```
isoEq     = margin + upl
frozenBal = isoEq + 挂单冻结
eq        = cashBal + isoEq
availBal  = cashBal − 挂单冻结(保证金 + 手续费)
```

### 全仓账务（**实测**）

与逐仓是**两套记账方式**，不是同一套的参数差异：

| | 逐仓 | 全仓 |
|---|---|---|
| 开仓时的现金 | 划走「保证金 + 手续费」 | **只扣手续费** |
| 仓位 `margin` | 有值 | **空串**——那笔钱从未离开现金 |
| 仓位 `imr` | **空串** | 有值 |
| 亏损吃掉的是 | 仓位保证金，与现金隔离 | 现金余额，同币种全仓仓位共担 |

字段关系（10 个快照、两个合约、含多仓位与挂单，最大差 `1.6e-13`）：

```
imr       = Σ仓位(名义/杠杆, 标记价) + Σ挂单(名义/杠杆, 委托价)
mmr       = Σ仓位(名义 × 档位率) + Σ挂单(名义 × 档位率)，两者都按标记价
ordFrozen = Σ挂单(名义/杠杆, 委托价)
availBal  = cashBal + 全仓浮盈 − imr − 逐仓挂单保证金 − 挂单手续费
frozenBal = isoEq + imr + 逐仓挂单保证金 + 挂单手续费
eq        = cashBal + isoEq + 全仓浮盈
```

只有逐仓持仓时全仓浮盈与 `imr` 均为零，上式退化为逐仓那一组。

**挂单在冻结与风险两侧取价不同**：保证金按**委托价**（那是真要掏的钱），维持保证金
按**标记价**（那是它此刻值多少）。实测一笔 5000 张的委托，`imr` 贡献
`62.625 = 5000×0.2505/20` 用委托价，`mmr` 贡献 `26.85 = 5000×0.358×0.015` 用标记价。

> 标定时踩过的坑：余额响应与持仓响应**并非同一瞬时**，两者之间有 `1e-4` 到 `1e-2`
> 量级的行情漂移。拿持仓算出来的数去对余额响应，漂移会盖过要验的东西——全仓浮盈
> 本身就只有 0.07 的量级。只用**单次响应内部**的字段互验，公式才立刻收敛到 `1e-14`。

### 挂单冻结

**实测**，差值为 0：

| 情形 | 冻结 |
|---|---|
| 开仓方向的挂单 | 张数 × (每张保证金 + 每张 **taker** 手续费) |
| 平仓方向的挂单 | **不冻结任何资金** |
| 反手委托 | 只对开仓那一段冻结 |

手续费一律按 **taker 费率**预冻结，即便该委托必然作为 maker 成交——实测一笔
远离市价、必然挂住的限价单也是按 taker 冻结的，OKX 取保守值。

### ⚠️ 杠杆决定了持仓量的天花板（**实测**）

档位表的杠杆上限逐档递减，反过来看就是——**选定了杠杆，也就选定了持仓量的上限**：

```
最大持仓量(杠杆) = 满足 tier.MaxLever >= 杠杆 的【最高】档位的 maxSz
```

实测 MASK-USDT-SWAP（一档 `[0,1000]` 杠杆≤50、二档 `[1001,2500]` 杠杆≤40、
三档 `[2501,22000]` 杠杆≤33.33）：

| 杠杆 | 最大持仓量 |
|---|---|
| 50 | 1000 |
| 40 | 2500 |
| 25 | 66000 |

三个都与 `max-size` 接口逐位相同。

**判据含同方向的开仓挂单：**

```
持仓 + 同方向开仓挂单 + 本单  ≤  最大持仓量(当前杠杆)
```

这一条由 OKX 的报文写明——「the sum of current order size, position quantity in the
same direction, and **pending orders in the same direction**」。实测持仓 600 张、
同方向挂单 300 张时，再挂 200 张（合计 1100）被拒，改挂 100 张（恰好 1000）通过。
平仓方向的挂单不占额度。

#### 顶格杠杆开满后再加仓：**直接拒单**

这是最容易想当然的一处。一档顶格杠杆开满之后再加一张，仓位会落进二档，而二档的
杠杆上限更低、容不下当前的杠杆。OKX 的处理是**根本下不出这一单**（`51004`），
而不是放行后让仓位降档：

```
50 倍杠杆下开满 1000 张 -> 成功，mmr 率 0.005（一档）
再加 1 张               -> 51004 拒绝
降到 40 倍后再加 1 张    -> 成功，mmr 率 0.0075（二档）
```

不校验的后果不是数字差一点：模拟器会走到一个真实账户上不可能存在的状态，
按二档的维持保证金率算出一套看着正常的风险指标，而实盘根本下不出这一单。

#### 相关的三个错误码

| 码 | 情形 |
|---|---|
| `51004` | 下单会让「持仓 + 同方向挂单 + 本单」超过当前杠杆下的最大持仓量 |
| `59102` | 设置的杠杆超过该品种的上限（第一档的 `maxLever`） |
| `59247` | 提高杠杆会让**现有持仓**超过新杠杆下的最大持仓量。OKX **拒绝改杠杆**，而不是把仓位强制减掉 |

### 可开张数

`GET /api/v5/account/max-size`。它是**两条约束取小**：

```
可开张数 = min( 按资金算的上限, 最大持仓量(当前杠杆) − 持仓 − 同方向挂单 )
```

实测 25 倍杠杆下按资金能开 33 万张，而杠杆那条线只允许 6.6 万张，OKX 返回 6.6 万。
**只算资金会在高杠杆下高估**——而高杠杆恰恰是杠杆这条线最紧的时候。

按资金那一侧：张数 = 可用余额 ÷ (每张保证金 + 每张手续费)，按 `lotSz` 向下取整。

有一侧要在委托价与标记价之间取**更保守**的一侧（张数更少者），另一侧直接按委托价
算。**是哪一侧取决于合约类型，两类恰好相反**（正向七组价格、反向五组价格全部命中）：

| | 取保守值的一侧 | 按委托价的一侧 |
|---|---|---|
| 正向 | `maxSell` | `maxBuy` |
| 反向 | **`maxBuy`** | **`maxSell`** |

这个翻转有统一的解释：**谁的保证金需求会随着行情往不利方向走而变大，谁就取保守值。**

- 正向名义是 `Q × px`，空头怕涨，涨则名义涨、保证金涨 → 空头保守
- 反向名义是 `Q / px`，多头怕跌，跌则名义涨、保证金涨 → 多头保守

判别力很强：偏离标记价 30% 的样本上，取错侧相差 30% 以上。

#### 全仓要多扣一项「开仓即产生的盯市浮亏」（**实测**）

```
正向  每张所需 = 每张保证金 + 每张手续费 + max(0, 委托价 − 标记价) × 合约面值   （买）
                                        + max(0, 标记价 − 委托价) × 合约面值   （卖）

反向  浮亏项改按倒数之差：max(0, 1/标记价 − 1/委托价) × 合约面值               （买）
                          max(0, 1/委托价 − 1/标记价) × 合约面值               （卖）
```

不利的方向两类合约一致：多头开在高于标记价、空头开在低于标记价，都是一成交就亏。

缘由是清楚的：**全仓的浮亏直接扣减可用余额**（保证金从未离开现金），而逐仓的浮亏
落在仓位保证金上、不动可用余额。所以以劣于标记价的价格开全仓，一成交就先亏掉一截
可用额度，能开的张数随之减少。

差距是数量级的。同一账户、同一 10 倍杠杆，标记价 2446：

| 委托价 | 方向 | 逐仓 | 全仓 |
|---|---|---|---|
| 1712.75 | 卖 | 122.49 张 | **30.74 张** |
| 3180.83 | 买 | 94.21 张 | **28.59 张** |

**只算不利的一侧**：以优于标记价的价格开仓会立刻产生浮盈，但 OKX 不让这笔浮盈撑起
更大的仓位——标记价 2446、以 1712.75 挂买单时 OKX 给 175 张，正是不含任何浮盈加成
的数。

逐仓**没有**这一项，两类合约共十二组价格全部确认。两种保证金模式在此分道扬镳。

### 持仓状态下改杠杆（**实测**）

改杠杆不只是改一个设定值——**逐仓会连带调整仓位保证金**：

```
改后权益（保证金 + 未实现盈亏）≥ 按新杠杆算的初始保证金  ->  保证金与现金分文不动
不足                                                  ->  从现金补足到恰好相等
```

⚠️ **方向最容易想反**：**降低杠杆要【补】保证金，提高杠杆什么都【不退】。**
提高杠杆确实让所需保证金变小，但 OKX 不把多出来的那部分退回现金，仓位就那么超额
担保着。三次提高杠杆（10→20、3→6、6→15）实测保证金与现金分文未动。

所需保证金按**开仓均价**算：`Q × avgPx / 新杠杆`。六次实测（SOL-USDT-SWAP 在
10/20/8/4/3/6/15 之间来回改），两次无标记价漂移的样本差 `1.1e-13` 与 `2.0e-14`。

这与「减保证金的下限」是同一条规则的两面：那边不许减到权益低于开仓初始保证金，
这边改杠杆后要把权益抬到它。

**全仓不走这条路**：保证金从未离开现金，改杠杆只改变被占用的 `imr`（实测
10x→102.27、3x→341.03、20x→51.175），现金分文不动，双向都可以自由改。

**仓位的 `lever` 字段随之改变**——不是只改设定值。依赖它的初始保证金、收益率、
强平价都会跟着变。

现金不足以补足时，OKX 拒绝改杠杆。另见「杠杆决定了持仓量的天花板」一节：提高杠杆
若会让现有持仓超过新杠杆下的上限，则返回 `59247` 并拒绝。

### 逐仓保证金增减

**实测**：`POST /api/v5/account/position/margin-balance` 一比一划转，杠杆设置不变，
强平价随之远离（追加 200 时 `62772 → 57750`）。

减少的下限是**开仓时的初始保证金** `Q × avgPx / lever`，等价于不允许有效杠杆
超过设定杠杆。越限时返回 `59301`。

下限按开仓均价而非标记价算：实测减到 `624.900524` 恰等于按开仓均价算出的初始
保证金，再减即被拒；若按标记价算下限应为 `624.96296`，比当时的保证金还高，
那样当前状态本身就已违规，与实际矛盾。

---

补充实测（v0.8.0 对拍时确认）：

- **新开仓位的保证金恰好等于下限**，`margin − Q×开仓均价/杠杆 = 0.000000`，
  因此一分钱都减不了，任何 reduce 都返回 59301
- **浮盈时减到恰好等于下限是允许的**：追加 10 后减回 10，保证金精确回到下限
- ⚠️ **浮亏会吃掉可减额，浮盈不会放大它**——这一条是 v0.9.0 最后一轮对拍才测出来的，
  此前的记载（「浮亏不会进一步收紧下限」）是错的，因为当时只在一个有浮盈的仓位上验过

```
可减额 = 保证金 − 开仓初始保证金 + min(0, 未实现盈亏)
```

两侧的证据：

| 情形 | 实测 |
|---|---|
| 浮亏 | 浮亏的仓位上减掉全部空间被 59301 拒绝；二分出的上限落在本式附近 |
| 浮盈 | 保证金恰在下限、浮盈 `+0.97` 的仓位，最大可减额是 **0** 而不是 0.97 |

边界上还有一点未定：二分测出的上限比本式略高（`1e-2` 量级），但测量期间浮亏本身
漂了同一量级，分辨不出是公式还有一项、还是取数时点所致。本库取保守的一侧——
宁可少减一点，也不放行 OKX 会拒绝的操作。

## 6. 资金费

**实测**，与真实账单逐位相同：

```
正向  资金费 = ctVal × sz × ctMult × 结算价 × 费率
反向  资金费 = ctVal × sz × ctMult / 结算价 × 费率        单位是标的币
fundingRate > 0：多头付空头
```

正向样本 `sz=49.18, px=2454.22, rate=0.0001` 算得 `1.206985396`，与账单逐位相同。

**反向已于 2026-09-01 实测。** 一次结算同时拿到逐仓与全仓两条路径：

| 合约 | 张数 | 结算价 | 费率 | 账单金额 | 残差 |
|---|---|---|---|---|---|
| BTC-USD-SWAP 逐仓 | 50 | 78513.8 | 0.0001 | `-0.0000063683072275` | `1.9e-17` |
| ETH-USD-SWAP 全仓 | 13600 | 2465.62 | 0.0001 | `-0.0055158540245456` | `5.0e-17` |

两个残差都是账单字段 16 位有效数字的截断，不是公式误差。**费率是独立取自
`funding-rate-history` 的，不是从金额反推的**——反推会让任何公式都自洽：把 `ctVal`
乘错、把除法写成乘法，反推出来的率照样能把金额还原，测试却一路绿灯。

账单的 `px` 字段即 OKX 用的结算价，与结算时刻的标记价一致。

**扣在哪里取决于保证金模式：**

| 模式 | 落点 | 依据 |
|---|---|---|
| 逐仓 | **仓位保证金**，不动现金余额 | 账单确证：连续多期结算中 `balChg` 恒为 0、`bal` 纹丝不动，而 `posBalChg` 恰为资金费金额、`posBal` 逐次递减 |
| 全仓 | **现金余额** | 全仓的保证金从未离开现金，仓位上的 `margin` 恒为空 —— 没有别的地方可扣 |

记错地方的后果不只是数字偏移：逐仓记到现金上会让逐仓权益与强平价一起算错；
全仓照逐仓的写法扣 `margin`，会因为 `margin` 恒为零而被夹零逻辑**静默吞掉**，
表现为持仓再久也不花一分资金费。

### 结算周期与费率上下限

**实测**采样 49 个永续：**16 个为 4 小时、33 个为 8 小时**，未观察到 1 小时周期。
**周期必须从 `fundingTime` / `nextFundingTime` 读取，不要硬编码。**

费率上下限也随合约而异，实测三档：`±0.01`（43 个）、`±0.0075`（4 个）、
`±0.00375`（2 个）。

### ⚠️ 历史费率只有约 3 个月

`funding-rate-history` 免鉴权可翻页，但**回溯窗口有硬限制**。实测翻到底：

| 合约 | 条数 | 最早 | 距今 |
|---|---|---|---|
| BTC-USDT-SWAP | 294 | 2026-05-25 | 97 天 |
| ETH-USDT-SWAP | 293 | 2026-05-25 | 97 天 |
| DOGE-USDT-SWAP | 293 | 2026-05-25 | 97 天 |
| BTC-USD-SWAP | 294 | 2026-05-25 | 97 天 |

四者截止在**同一天**，说明这是平台级窗口而非个别合约的问题。

**后果：超出约 3 个月的回测取不到真实资金费率。** 结算机制本身已按真实账单
验证无误，但它只在调用方能提供费率时才有意义。长周期回测须自行选择：接第三方
数据源、用常数近似（观测到的费率多为 `0.0001`，即 OKX 的基础利率），或不计
资金费——最后一种会**系统性高估多头持仓的收益**。

## 7. 强平

### 触发

**实测**：`mgnRatio ≤ 1`，即权益 ≤ 维持保证金 + 平仓手续费。

判据用**标记价**而非最新成交价——用最新价会让插针扫掉本不该爆的仓位。

两种模式的**触发层级**不同：

| 模式 | 层级 | 权益 |
|---|---|---|
| 逐仓 | 仓位级，各爆各的 | 该仓位的保证金 + 浮盈 |
| 全仓 | **结算币种级**，同币种的全仓仓位共担一份权益 | 现金余额 + 全仓浮盈 |

因此全仓下任一合约的行情变动都可能把整个币种推过强平线——回测循环里推进某个
合约的 K 线后，必须把该结算币种整体再看一眼，而不只是看这个合约的仓位。

### 结算方式

**实测**，取自一次真实的全部强平。样本：BTC-USDT-SWAP 空头 0.15 张 @ 78099，
100 倍杠杆，保证金 `1.171485`，强平价 `78526.61`。

```
订单     category='full_liquidation'  ordType=limit  reduceOnly=true
         成交价 78566.58（已越过强平价）  pnl=-0.70137  fee=-0.058924935
仓位历史  liqPenalty=-0.47139948   realizedPnl=-1.290268665
账单     type=5  subType=105   balChg=0   posBalChg=-1.231694415
         type=10 subType=108   balChg=0   posBalChg=+0.060209415
```

由此确定的规则，各项差值均为零：

| 项 | 规则 |
|---|---|
| 成交价 | **触发时的市价**，可能已越过强平价 |
| 盈亏 | 按该成交价计算 |
| 手续费 | 名义价值 × taker 费率 |
| **爆仓罚金** | **名义价值 × 维持保证金率**（`0.47139948 / 117.84987 = 0.004`，正是 mmr） |
| 损失 | **封顶为该仓位的保证金**；超出部分以单独账单退回 |
| **现金余额** | **`balChg = 0`，自始至终不变** |

两笔账单之和 `-1.231694415 + 0.060209415 = -1.171485`，恰好等于开仓保证金——
**保证金不多不少全额损失**。

净已实现盈亏也精确对上：
`开仓费 -0.05857425 + 平仓盈亏 -0.70137 + 平仓费 -0.058924935 + 罚金 -0.47139948
= -1.290268665`，与 `positions-history` 的 `realizedPnl` 一致。

> 早先曾按「成交于费后破产价、罚金为零」建模。净效果相同——保证金全损、现金不变
> ——但 `pnl`、`fee`、`liqPenalty`、`realizedPnl` 四个字段全都对不上。
> **净效果相同不等于字段相同**，而字段级同构正是本项目的验收标准之一。

常态强平也会有小幅超出——触发与成交之间价格总会再走一点，实测那次为 `0.0602`，
占保证金的 5%，OKX 以单独账单退回。「常态超出为零」是错的期望。

### 阶梯减仓（**实测**）

真实链路是 `撤单 → 阶梯部分减仓 → 全部强平 → 超额退回`。减仓后持仓量落入更低档位，
维持保证金率随之下降，仓位有机会被救回。

**已由一次真实事件逐项确证**：FIL-USDT-SWAP 空头 50 万张 @ 0.6745872328、40 倍杠杆、
保证金 843.234041。账单把链路写得很明白：

| subType | 含义 | 张数 | 成交价 |
|---|---|---|---|
| `101` | 部分强平（阶梯减仓） | 250000 | 0.6809 |
| `105` | 全部强平 | 250000 | 0.6877 |
| `108` | 穿仓补偿退回 | 1.661819 | — |

第一次减到一档上限后价格继续走，第二次才全平——**不是一步到位**。

对上的部分：

- **减仓量**：500000 → 250000，即减到一档上限
- **盈亏与手续费**：`pnl = Q×(开仓均价−成交价)`、`fee = 名义×taker`，两次都逐位精确
- **损失封顶**：两次扣减合计 844.895860，退回 1.661819，净损失 **843.234041 恰好等于
  仓位保证金**，差为 0
- **现金不动**：`balChg` 全程为 0
- **净额口径**：`realizedPnl = pnl + fee + liqPenalty = -861.760540819995`，逐位相同

⚠️ **两处此前算错的，都由这次事件照出来：**

**一、罚金按【减仓后】所在档位的维持保证金率算。** 减仓前在二档（`mmr 0.015`）、
减仓后在一档（`0.01`），实际罚金 170.225 / 名义 17022.5 = **0.01**。按减仓前算会多收
85.11。

> 同一样本无法区分另两种解释：「被减掉的那部分自己查档」（25 万张也落在一档）与
> 「目标档位的率」。三者在这里给出同一个数——要区分得有一次从三档减到二档、而被减
> 部分落在一档的样本。

**二、保证金按实际发生的盈亏、手续费与罚金扣减，不是按张数比例释放。** 普通的部分
平仓才是比例释放（实测 624.705284 平掉四分之一释放 156.176321）；强平减仓不把任何
东西释放回现金，只是把损失从仓位保证金里扣掉。实测保证金 843.234041 的仓位第一次
减仓后 `posBal` 变为 506.678611，差值恰为 `pnl+fee+罚金 = -336.555430`，而按「减半」
会得出 421.617，差 85.06。

> 两处错误的差额恰好相同（85.11 与 85.06），因为它们同源——都来自那 0.005 的
> 维持保证金率之差。

### 全仓强平的结算方式（**未定**）

触发判据本身是可靠的（保证金率的公式经 13 个真实快照逐项核对），但**触发之后
OKX 究竟怎么了结，本项目没有观察到**——真实全仓爆仓需要一个不带对冲的裸仓位吃掉
整个币种的现金，而模拟盘上的资金规模不足以在可控时间内复现。

当前实现是照**已实测的逐仓强平**平移过来的：按标记价成交、收一笔吃单手续费、
再收一笔等于维持保证金的罚金，损失封顶、超额由风险准备金承担。与逐仓有两处必然
差异：

| | 逐仓 | 全仓 |
|---|---|---|
| 损失的来源 | 划入仓位的保证金，现金不动 | 保证金从未离开现金，故盈亏/手续费/罚金直接落在现金上 |
| 封顶的口径 | 该仓位的保证金 | 该币种的全仓权益 |

**阶梯减仓在全仓下未建模**：当前一律全平该币种的全部全仓仓位。真实 OKX 在全仓下
也会先做阶梯减仓，结果比全平温和；本实现偏保守，回测里表现为**高估**爆仓的杀伤力，
而不是低估。

## 8. 算法委托

### 不占用任何资金（**实测**）

挂四张计划委托后 `availBal` / `ordFrozen` / `imr` / `mmr` **全部纹丝不动**。

算法委托不进订单簿，它只是一条「价格到了就下单」的规则。把它当普通挂单去冻结
资金，回测里会凭空少掉一大块可用额度——这是最容易想当然搞错的一条。

资金够不够要等触发那一刻才算。届时若不足，该委托转入 `order_failed`。

### 触发后生成一笔普通委托（**实测**）

`state` 由 `live` 变为 `effective`，`ordId` 字段带出一笔真实委托，其
`ordType=market`、`state=filled`，与手工市价单毫无二致。

也就是说算法委托本身不成交，它只负责在条件成立时**下一笔普通单**，
后续的撮合、手续费、盈亏核算全部走既有路径。

| `ordPx` | 触发后 |
|---|---|
| `-1` | 市价委托 |
| 具体价 | 限价委托，随后走正常撮合 |

> 实测一次真实触发：`triggerPx=2451.68`，市价单成交在 `2451.67`，即低一个 `tickSz`。
> 本库**不建模这一档滑点**，成交价取触发价——有深度数据才谈得上滑点，没有就不该
> 凭空造一个数。夹具里留了一条守卫，差距一旦超出一个 tickSz 的量级就报警。

### 各类型与触发价类型（**实测**）

| 类型 | 说明 |
|---|---|
| `trigger` | 计划委托，单条腿 |
| `conditional` | **只认一条腿**。同时提交 tp 与 sl 两组参数时 OKX 只保留 sl，另一组被丢弃**且不报错** |
| `oco` | 两条腿并存，任一触发则整笔作废 |
| `move_order_stop` | 移动止盈止损 |

触发价类型 `last` / `index` / `mark` 三种都接受，默认 `last`。

### 移动止盈止损的棘轮（**实测**）

```
平多的卖单  moveTriggerPx = 最高价 × (1 − callbackRatio)
平空的买单  moveTriggerPx = 最低价 × (1 + callbackRatio)
```

两条性质都由实测确认，双向各追踪 40 次采样：

- **极值自挂单起算**，不需要先出现一段有利行情。挂单瞬间的触发价就是
  「当时价格 × (1 ∓ ratio)」
- **只朝一个方向棘轮**，零回退。平多那条腿的触发价 40 次采样中一次没降过，
  平空那条一次没升过

> 采样是 4 秒一次而 OKX 逐笔跟踪，因此按采样估的极值必然不如它极端——实测平多
> 那条腿的真实触发价**总是不低于**按采样最高价算出的值，平空那条**总是不高于**。
> 这个偏差的**单边性**本身就是「跟极值」的证据：若它跟的是别的东西，偏差不会单边。

### ⚠️ 一根 K 线只给区间，不给路径

这是回测特有的、真实交易里不存在的问题，本库的取舍写在这里：

| 价格类型 | 判据 | 分辨率 |
|---|---|---|
| `last` | `[Low, High]` 整段 | 最细 |
| `mark` / `index` | 「上一步的值 → 本步的值」这一段 | 更粗，一根 K 线只有单点值 |

**不拿最新价去顶替标记价或指数价**——那是另一个价格，顶替会让触发点系统性偏移。
指数价未提供时给出原因而不是悄悄跳过。

**移动止损先按本步的有利极值棘轮，再判触发。** 这等于假定有利的那一段先发生，
于是波动大的一根 K 线更容易触发止损；反过来假定不利的一段先发生，同一根 K 线可能
完全不触发。两者都可能是真实路径，从 OHLC 无从分辨。选前者是因为它对策略更保守
——止损触发得更频繁，回测里不会凭空多出一批本该被扫掉的长趋势。

## 9. 下单校验

**实测**：

- **超量平仓会被裁剪而非拒绝**。提交 1.50 张去平一个 0.15 张的仓位，OKX 把 `sz`
  直接裁剪到 0.15 后成交（订单记录里的 `sz` 就是 0.15）。
- **数量必须是 `lotSz` 的整数倍**，否则返回 `51121`。实测 459 个永续的 `minSz`
  与 `lotSz` **全部相等**，故「低于最小下单量」与「非整数倍」是同一件事。
- **价格超精度不会被拒绝**，OKX 按方向取整后接受：

```
买单  2150.51 / 2150.55 / 2150.59  →  2150.5   向下截断
卖单  2376.91 / 2376.95 / 2376.99  →  2377     向上进位
```

三个合约、`tickSz` 横跨 `0.1 / 0.01 / 1e-7`，无一被拒。两个方向都朝远离市价的
一侧移动，即让委托更不激进。

**因此模拟器不应强制校验价格精度**——强制拒单会拒掉真实 OKX 会接受的订单，
回测中凭空少掉成交，与还原真实行为正好相反。

## 10. ⚠️ 模拟盘 ≠ 生产环境

**实测**。这是对拍策略中最容易埋雷的一点。

| 合约 | 字段 | 生产 | 模拟盘 |
|---|---|---|---|
| BTC-USDT-SWAP | tickSz | 0.1 | **0.01** |
| DOGE-USDT-SWAP | tickSz | 0.00001 | **0.0000001** |
| YFI-USDT-SWAP | tickSz | 1 | **0.1** |
| YFI-USDT-SWAP | lever | 20 | **50** |
| BTC-USD-SWAP | lever | 100 | **125** |

档位表差异更彻底：

| 品种 | 差异 |
|---|---|
| BTC-USDT / ETH-USDT | 档位区间上界是生产的 **10 倍**（BTC 首档 1000 → 10000），99 档全部不同 |
| BTC-USD | 档位数 **99 vs 100**，且 `imr` 0.01 → 0.008、`maxLever` 100 → 125 |

**对拍工具必须从它所交易的同一环境拉取规则数据。** 拿生产快照去对拍模拟盘，
每个依赖档位、价格精度或杠杆的计算都会偏，而偏差看起来像模拟器自身的缺陷，
会把大量时间浪费在追查根本不存在的问题上。

随库分发的内置快照取自**生产环境**，仅供回测；对拍模拟盘须用
`live.WithSimulated(true)`。

## 11.5 降级的两只手（本库的取舍规则）

数据供不上时，模拟器要么拒绝、要么降级。本库一度看着像有两条打架的立场：
`Funding` 留空即不计资金费（允许降级，写明偏向），而 `IdxPx` 留空则跳过该委托
并说明原因（拒绝顶替）。其实是一条规则的两只手：

```
可避免、且会改变离散事件的降级    ->  默认拒绝
不可避免、或只造成连续偏差的降级  ->  默认允许，但写明偏向
```

| 数据 | 可避免？ | 错的性质 | 落在哪只手 |
|---|---|---|---|
| 资金费率 | **否**，`funding-rate-history` 实测翻到底仅 93 天 | 连续偏差：系统性高估多头收益 | 允许，写明 |
| 指数价 | 是 | 离散：`index` 类型算法委托触不触发 | 拒绝顶替，跳过并说明 |
| 标记价 | **是**，见下 | 离散：强平有没有发生 | **拒绝**（v1.0 起默认） |

标记价可避免这一条是实测的：`history-mark-price-candles` 与 `history-candles`
**同深**——2025-01-01 与 2024-01-01 两者都取得到，2022-01-01 两者都取不到。
也就是说，**取得到回测所需的价格数据，就一定取得到对应的标记价**。

标记价此前被放错了手：缺失时静默退回最新成交价。用最新价做强平判据会让插针扫掉
本不该爆的仓位——对尾部风险就是强平的策略（如做多网格）是假阴性，参数组合被淘汰
而扫描结果里不留痕迹。

`Config.RequireMarkPx` 已提供，**v1.0 起默认为真**。


## 12. 尚未定论

代码中不臆造这些规则，并留有守卫测试防止前提悄悄失效。

**费率组与结算币种变体的优先级。** 实测 459 个永续的 `groupId` 均为 4，且 SWAP
费率表 1..7 组与 `maker/taker/makerU/takerU` 取值完全一致，两条路径给出同一个
数字，无从判定。现采用**费率组优先**——这是使用者拍板的决定而非实测结论，
依据是现货各费率组差异显著，说明它是 OKX 用于精细区分的维度。
`TestSwapFeePathsCurrentlyAgree` 会在两条路径开始分歧时失败。

**阶梯减仓路径（全仓）。** 见 §7。逐仓那条已于 2026-08-31 实测确证；全仓这条仍未实测，当前一律全平该结算币种的全部全仓仓位。

全仓这条难在**保证金率有结构性下限**（见 §4）：`1/(最高杠杆 × (mmr率 + 吃单费率))`，
由档位表锁死，转出资金或烧手续费都压不到 1，只能等一次真实的不利波动。

**挂单是否计入全仓的查档张数。** OKX 确实把挂单算进了币种级的 `imr` 与 `mmr`，
但实测样本中持仓本身已在第二档、挂单也按第二档的 `0.015` 计，无从分辨查档张数
里有没有它。当前实现按【现有持仓】合并后的档位计算，不把挂单张数算进去——
只建模到证据所及之处。

**反向合约的资金费。** 形态由名义价值公式推得（`Q/结算价 × 费率`，单位是标的币），
但未经实测——验证它要等一次真实结算，周期 8 小时，且账户须在结算时刻持有反向仓位。
正向的形态已由 20 条真实账单逐位确证。

**算法委托的部分成交与 `closeFraction`。** 本库的算法委托一次性下满 `sz`，未建模
按仓位比例平仓（OKX 的 `closeFraction`），也未建模触发后限价单只成交一部分时算法
委托的 `partially_effective` 状态。前者是参数形态问题，后者要撞上部分成交才观察得到，
而本库明确不建模部分成交（没有深度数据）。

**触发后的滑点。** 实测一次真实触发：`triggerPx=2451.68`，市价单成交在 `2451.67`，
低一个 `tickSz`。只有一个样本，且滑点本就取决于当时的盘口深度——本库不建模它，
成交价取触发价，并在夹具里留了守卫：差距超出一个 tickSz 的量级就报警。

**含挂单时全仓保证金率的分母。** 无挂单时 `(现金+全仓浮盈)/(mmr+Σ仓位平仓费)`
在 9 个快照上差 `5e-15`；唯一一个含挂单的快照上残差为 `2e-4`（相对），量级远小于
其他候选（差 0.25 与 172）但并非精确命中。同一快照中不含挂单的样本也有 `3.5e-4`
的残差，且其币种 `mmr` 与各仓位 `mmr` 之和相差 0.021——说明币种级字段与持仓响应
不在同一 tick，残差更可能来自 OKX 自身的取数时点而非公式。只有一个样本，不硬拟合。

## 13. 建模时的高风险点

按踩坑代价排序。前五条已在本实现中处理，后两条属于尚未支持的范围。

1. **档位表的键是 `(instType, instFamily, mgnMode)`，不是 `instId`**（§4）。
   按 `instId` 建模后期必须推倒重来——因此数据模型第一天就要以 `instFamily`
   为聚合键。漏掉 `instType` 则会让永续与交割串表，两者的一档上限实测差 8 倍。
2. **两种模式的查档口径互补**（§4）：全仓按家族**绝对值**合计，逐仓每个仓位单独查。
   写反了任何一侧，维持保证金率都会差 50% 以上，而且只在多仓位场景才暴露。
3. **买卖模式的反手**（§3）。常见错误是把整笔成交都当成平仓（盈亏算多），
   或都当成开仓（漏掉已实现盈亏）。
4. **字段语义陷阱**（§2）。名字与含义不符的字段有七个之多。
5. **全仓强平是结算币种级的**，逐仓才是仓位级（§7）。两者是完全不同的代码路径，
   不要试图复用——全仓仓位的 `margin` 恒为空，拿它去算损失只会得到零。
6. **组合保证金 (acctLv=4) 的 MMR 由压力测试矩阵得出**，不是查表。
   工作量约等于本项目其余部分之和，已明确排除在 v1.0 范围外。
7. **跨币种保证金 (acctLv=3)** 需要折算率、跨币种借币计息与账户整体 USD 折算。
