# 版本排期

> 定稿于 2026-08-31。范围与决策依据见 [design.md](./design.md)。

## 分支与发布约定

| 分支 | 角色 |
|---|---|
| `main` | 只接受来自 `dev` 的合并，每次合并打 `vX.Y.Z` tag，保持永远可 `go get` |
| `dev` | 默认开发分支，日常提交落这里 |
| `feat/*` `fix/*` | 仅当改动会持续多天且打断 dev 时才开，完事 squash 回 dev |

Go 库特有约束：

- **tag 必须打在 `main` 上**，严格 semver（`v0.1.0`），`go get` 只认这个。
- **v1.0.0 之前 API 可自由变更**（v0 不受兼容性承诺约束）—— 要充分利用这个窗口把 API 打磨定型。
- 一旦发布 `v2`，module path 必须加 `/v2` 后缀，很烦。**因此 v1.0.0 是一道必须谨慎跨过的门。**

## 已完成：v0.1.0

范围较初稿有一处扩大。原计划把「定期自动拉取」放在 v0.8.0，但使用者指出
**OKX 规则会变、用户费率等级也会变**，这意味着「可定期自动拉取 + 部分参数可调」
本就是规则数据层的形态，而不是一个可以事后附加的功能。若按初稿先做成静态快照，
后面加自动刷新时 Provider 的接口形态要重做。因此并入 v0.1.0。

实际交付超出初稿的部分：

- `refdata/live` 定期自动拉取，含**规则变更检测**——只换数据不告知变更，
  等同于定时重启，而档位表或合约面值的变动会直接改变仓位风险指标
- 费率表的 `WithRate` / `WithLevel` 覆盖机制
- 快照持久化（确定性序列化，可纳入版本控制做 diff）
- `cmd/refdata-sync` 快照生成工具

## 一处由使用者提出的排期调整

原计划 v0.3.0 做全仓模式。使用者指出：本库的核心用途是供回测引擎调用，而回测
引擎每根 K 线都要问「这单挂得起吗、能挂多少、成交后仓位会怎样」，而追加保证金
这类操作在策略回测里可能整个跑完都用不上一次。

据此把**预下单计算与挂单冻结**提到 v0.3.0，全仓顺延。这个判断是对的——
Balance.OrdFrozen 此前虽有字段却恒为零，属于我漏掉的真实缺口。

双向持仓已在 v0.2.0 一并完成，故其后各版本相应顺延一位。

## 已完成：v0.2.0

买卖模式与开平仓模式**都已支持**（原计划只做买卖模式，但仓位状态机同时处理两者
几乎不增加成本，且模拟盘账户本身就是开平仓模式，对拍需要）。

公式与规则一律先在模拟盘上标定再写代码。这一版标定出的、文档里查不到的规则：

- **强平价含一个 tickSz 的安全缓冲**，多头加、空头减。四个样本横跨 tickSz 为
  0.01 / 0.1 / 1e-7 三个量级，偏移与 tickSz 的比值全部为 ±1
- **收益率的分母是开仓时的初始保证金**，不是当前 margin。两者仅在持仓久了、
  资金费从逐仓保证金扣走后才分离，只有持有七周的样本能区分
- **部分平仓按张数比例释放保证金**，差值恰为 0
- **减少保证金的下限是开仓初始保证金**，越限返回 59301
- **OKX 从不因价格超精度拒单**，只按方向取整（买单向下、卖单向上）
- **模拟盘与生产环境的规则数据不同**，档位区间可相差十倍

### 覆盖缺口

逐仓保证金增减不在对拍工具的比对范围内：所用 SDK 尚未封装
`POST /api/v5/account/position/margin-balance`，也没有导出通用的已签名请求方法。
为一个接口手写 HMAC 签名会把安全敏感代码复制一份出来、日后必然漂移。
该功能的规则已由直接探测标定并有单测覆盖，待 SDK 补上后纳入。

## 一处对早期计划的修正

原本打算把对拍推到 v0.8.0 才做。**这是错的** —— 那样会让 v0.2 到 v0.7 全部建立在「我对 OKX 规则的理解」之上，
而这套理解一旦某处有偏差，会被单测一起固化，直到 v0.8.0 才暴露，届时返工面积极大。

**改为：v0.2.0 就建立最小可用的对拍工具，之后每个版本同步扩展它。**
v0.8.0 的职责相应改为"加固与差异清零"，而不是"从零建对拍"。

## 明确排除在 v1.0 之外

- 组合保证金模式 acctLv=4（MMR 由压力测试矩阵得出，工作量约等于其余全部之和）
- 跨币种保证金模式 acctLv=3（折算率 haircut、跨币种借币计息、账户整体 USD 折算）
- 期权
- ADL 自动减仓（排队依赖全市场持仓与收益率，回测环境无法还原）
- 假 OKX HTTP 服务端
